# KOSPI 차월 수익률 예측

금융데이터인텔리전스 2026년 2학기 팀05 프로젝트.
기업 특성과 통화정책·경제뉴스 정보를 활용하여 KOSPI 보통주의 차월 수익률과 종목 간 상대순위를 예측한다.

## 1. 프로젝트 목적

기준월 말까지 이용 가능한 정보가 차월 종목별 수익률의 상대순위를 설명하는지 검증한다. 정형 금융 특징을 사용하는 기준모형에 정책·뉴스 특징을 추가하고, OLS·Ridge·MLP를 같은 종목·기간·검증 구간에서 비교한다.

핵심 평가 지표는 월별 **Spearman Rank IC**다. 각 가설의 예상 방향과 실제 검증 결과는 구분한다.

### 연구 대상과 용어

| 항목 | 정의 |
| --- | --- |
| 연구 대상 | 현재 또는 과거 KOSPI에 상장된 보통주 |
| 관측 단위 | 종목 `i` × 기준월 `t` |
| 기준월 `base_month` | 특징을 구성하는 정보의 기준 월 |
| 목표월 `target_month` | 기준월의 다음 달 달력월 `t+1` |
| 목표값 `y` | 목표월의 개별 종목 수정 월수익률 |
| 예측값 `yhat` | 모형이 예측한 목표월 수익률 |
| 특징 | 기준월 말까지 공개된 자료로 구성한 설명변수 |
| PIT 결합 | 해당 시점에 실제 이용 가능했던 정보만 연결하는 방식 |

종목별 행 순서가 아니라 달력월로 목표값을 연결한다. 예를 들어 2001년 1월 목표수익률에는 2000년 12월 기준 특징을 사용한다.

## 2. 연구 가설과 특징 정의

### H1. 복합 금융 팩터

**소형주·고장부가치비율·정모멘텀 특성을 결합한 점수가 높을수록 차월 수정 월수익률의 상대순위가 높을 것이다.**

규모·가치 요인과 과거 수익률 지속성을 바탕으로 다음 특징을 결합한다.

```text
Size(i,t) = ln(월말 시가총액)
B/M(i,t)  = t월 말까지 공개된 유효 자기자본 / 월말 시가총액
Mom(i,t)  = ∏[1 + R(i,s)] - 1,  s = t-11, ..., t-1
H1(i,t)   = [-Z(Size(i,t)) + Z(B/M(i,t)) + Z(Mom(i,t))] / 3
```

- 시가총액과 자기자본은 양수여야 한다. 자기자본은 연결 지배기업 소유주지분을 우선하고, 대체 계정·별도재무제표를 사용하면 근거를 기록한다.
- Mom은 기준월을 제외한 정확히 11개 달력월의 누적수익률이다. 한 달이라도 빠지면 기간을 줄여 계산하지 않는다.
- 세 구성값이 모두 유효한 당월 공통 종목집합에서 평균과 표본표준편차(`ddof=1`)로 각각 표준화한다.
- 종목 수가 2개 미만이거나 표준편차가 0이면 미산출 처리한다. 미래 목표수익률의 관측 여부로 표준화 집합을 선택하지 않는다.

2001년 1월 목표의 기준월은 2000년 12월이며, 모멘텀에는 2000년 1~11월 수익률을 사용한다.

### H2. 통화정책 커뮤니케이션과 기업규모

**기준월 말까지 이용 가능한 통화정책 발표문의 완화적 정책기조가 강할수록, 기업규모가 작은 종목의 차월 수정 월수익률 상대순위가 높을 것이다.**

```text
정책기조 점수 = (완화 표현 수 - 긴축 표현 수) / (완화 표현 수 + 긴축 표현 수)
소형주 점수 = -Z[ln(직전 월말 시가총액)]
H2 결합 변수 = 정책기조 점수 × 소형주 점수
```

정책기조 점수는 값이 높을수록 상대적으로 완화적(dovish), 낮을수록 긴축적(hawkish)으로 정의한다. 분모가 0이면 기조 식별 불가로 기록하고 유효한 점수 0과 구분한다. 정책 사전과 문맥 규칙은 2001~2021년 Train 내부에서 확정하고 Test 수익률을 참고해 수정하지 않는다.

기업규모는 직전 월말 시가총액의 자연로그를 같은 기준월의 유효 종목에서 Z-score(`ddof=1`)로 표준화한 뒤 부호를 반전하여 값이 클수록 상대적으로 작은 기업을 나타내도록 한다. 정책기조 점수, 소형주 점수, 두 값을 결합한 변수를 함께 보존한다.

실제 공개일을 확인할 수 있는 문서는 해당 공개일을 사용한다. 확인이 어려운 과거 자료에서 회의일을 대용 시점으로 사용할 경우 proxy 여부를 별도 기록한다. 무발표가 확인된 월에는 직전 공개 기조를 유지하지만 수집·추출 실패는 결측과 사유를 남긴다. 동일 월에 여러 발표문이 있으면 월말까지 이용 가능한 가장 최근 문서를 사용한다.

### H3. EWMA 총변동성

**종목별 EWMA 총변동성이 높을수록 차월 수정 월수익률의 상대순위가 낮을 것이다.**

수정 월수익률로 분산 상태를 누적하고 최근 관측 가용성을 충족한 월에 변동성을 공개한다.

```text
초기화: 최초 유효 수익률 10개의 표본분산(ddof=1)을 v(i,τ)로 설정
갱신:   v(i,t) = 0.97 × v(i,t-1) + 0.03 × R(i,t)²
결측월: v(i,t) = v(i,t-1)
원 특징: sqrt(v(i,t))
```

- 초기화한 10번째 관측월 `τ`의 수익률을 재귀식에 다시 반영하지 않는다.
- 전체 이력에서 상태를 이어가며 12개월·연도·Fold마다 재초기화하지 않는다.
- 최근 12개 달력월 `t-11~t` 중 유효 수익률이 10개 이상일 때만 특징을 공개한다. 조건 미달 시 해당 월 특징은 결측으로 두고 상태는 보존한다.
- `sqrt(v)`를 월별 표본표준편차(`ddof=1`)로 표준화한다. 유효 종목 부족이나 표준편차 0은 미산출 처리한다.

H3는 기준월 `t`의 수익률을 포함하며, 개별 종목의 총변동성을 측정한다.

### H4. 뉴스 불확실성과 모멘텀

**경제뉴스 불확실성이 높은 달에는 모멘텀과 차월 수정 월수익률 사이의 양의 관계가 약해질 것이다.**

```text
뉴스 비율 = 불확실성 사전에 적중한 기사 수 / 같은 경제 검색조건으로 수집한 기사 수
H4 상호작용 = 뉴스 비율 × Mom
```

뉴스 비율, 원 모멘텀, 두 변수의 상호작용을 함께 사용한다. 선형모형의 상호작용계수가 음인지와 추가 예측력을 검증한다. Mom은 H1과 동일한 11개 달력월 누적수익률을 사용한다.

기사는 URL·제목·발행일로 중복을 확인하고, 여러 표현이 적중해도 분자에서 기사당 한 번만 센다. 정상 수집에서 적중 기사 0건은 유효한 비율 0이며, 전체 기사 0건이나 수집 실패는 별도 사유로 기록한다. 뉴스 비율은 수집 표본의 불확실성 대리변수다.

## 3. 데이터와 정보시점

### 데이터 구성

| 자료 | 용도 | 출처·범위 |
| --- | --- | --- |
| 월간 패널 | 수정 월수익률·월말 시가총액·기업정보; H2 기업규모 | 기본 제공 파일, 준비·학습용 2000~2021년 |
| 재무 공시 | H1 자기자본 | OpenDART 우선, 과거 미조회 자료는 DART 원문·KIND 확인 |
| 정책 발표문 | H2 정책기조 점수 | 한국은행 통화정책방향 발표문, 2001~2021년 |
| 경제뉴스 | H4 불확실성 기사 비율 | 네이버 뉴스 API 우선, 부족 구간은 이용조건을 확인한 웹 수집으로 보완 |
| 시장 보조자료 | 시가총액 대조·종목 이력·시장 국면 확인 | marcap 및 ECOS KOSPI 지수 |

외부자료의 실제 가용기간과 누락범위는 수집 후 확인한다. 정책·뉴스 사전과 검색조건은 미확정 항목이다. 뉴스는 2001·2010·2021년의 같은 표본 월을 먼저 대조하며 API의 기간 요청·검색 위치 제한을 고려한다.

### 공통 입력 형식

| 파일 | 주요 항목 |
| --- | --- |
| `panel.csv` | 종목코드, 관측월, 수정수익률, 시가총액, 종목 적격 여부 |
| `security_map.csv` | 종목코드, 기업번호, 유효 시작·종료일, 연결 근거 |
| `dart.csv` | 기업번호, 회계기간, 공개시점, 접수번호, 자기자본, 연결·별도, 계정, 단위, 정정 버전 |
| `documents.csv` | 문서 ID, 출처, 공개시점, 원문 경로, 수집 상태; 뉴스 제목·요약·발행일·URL·수집방식 |

종목코드는 6자리 문자열, DART 기업번호는 8자리 문자열로 관리한다. 월은 `YYYY-MM`, 수익률은 소수, 금액은 원 단위를 사용한다. 원본 열 이름과 적격 여부의 출처를 확인하고 공통 필드에 대응시킨다.

### 시점·결측 처리

- 한국시간 기준 월말까지 실제 공개된 유효 정보를 사용한다. H2는 실제 공개일을 우선하며, 확인이 어려운 과거 발표문에서 회의일을 대용하면 proxy 여부를 별도 기록한다.
- 공개일 불명 자료는 제외한다. 월말에 공개됐지만 공개시각이 불명인 외부 공시·문서는 다음 기준월부터 반영한다.
- 정정공시를 과거에 소급하지 않는다. 시장 월말 값은 마지막 거래일 종료 후 확정된 값을 사용한다.
- 종목과 기업번호는 당시 유효한 대응표로 연결한다. 코드 재사용·합병·상폐의 불명확한 연결은 사유를 남긴다.
- 실제 0, 자료 부재, 수집·추출·연결 실패를 구분한다. 결측을 0이나 전체기간 평균으로 채우지 않는다.
- 원본과 출처·이용조건을 보존한다. 재배포 제한 자료는 목록과 합법적 재수집 절차로 관리하며 API 인증정보는 환경변수에 둔다.

## 4. 기간 분할과 검증

분할 기준은 `target_month`다.

| 구간 | 기간 | 사용 범위 |
| --- | --- | --- |
| Warmup | 2000년 | 특징·과거 시차·EWMA 초기화. 모형 학습·평가 제외 |
| Train | 2001~2021년 | 모형 학습·내부 검증·설정 선택 |
| Test | 2022~2025년 | 설정 고정 후 한 번 최종평가 |

연 단위 Expanding Window는 다음과 같이 구성한다.

```text
2001~2005 학습 → 2006 검증
2001~2006 학습 → 2007 검증
...
2001~2020 학습 → 2021 검증
```

총 16개 Fold를 사용한다. 추가 학습형 전처리 변환기는 해당 Fold의 학습행만으로 적합한다. 외부자료 하위기간도 최소 5년 학습 후 다음 해를 검증하며, 이력이 부족하면 해당 확장 검증을 보류한다.

기준모형은 H1·H3와 목표값이 모두 유효한 공통 종목·월 표본을 사용한다. H2·H4 확장 시에는 해당 자료가 겹치는 종목·월로 기준모형도 다시 학습·평가한다. 특징 계산·표준화가 끝난 뒤 목표값을 연결하고, 특징 결측과 목표 결측 사유를 분리한다.

## 5. 예측모형과 평가 기준

### 모형 후보

| 모형 | 설정 |
| --- | --- |
| OLS | 절편 포함 선형회귀 |
| Ridge | 절편 포함, `alpha={0.01, 0.1, 1, 10, 100}` |
| MLP | 은닉층 `(32,)` 또는 `(64,32)`, `alpha={0.0001, 0.01}` |

MLP 공통 설정은 ReLU, Adam, 학습률 `0.001`, 배치 `256`, 최대 반복 `500`, 난수값 `42`, `shuffle=False`, `early_stopping=False`다. 은닉층과 alpha를 조합한 기본 후보는 4개다.

후보는 공통 유효 검증월의 평균 Rank IC로 선택한다. 동률이면 Ridge는 큰 alpha, MLP는 은닉층 총 노드 수가 적은 후보와 큰 alpha를 순서대로 우선한다. 수렴 실패 후보는 사유를 기록하고 제외한다.

### 월별 Spearman Rank IC

예측과 실제수익률을 종목·목표월로 1:1 연결하고 월별 순위상관을 계산한다. 동순위는 평균순위를 사용한다.

- 유효 종목이 3개 미만이거나 예측·실제 순위 중 하나가 상수이면 IC를 미산출 처리한다.
- 미산출 IC는 0으로 대체하지 않고 사유를 기록한다.
- 공통 유효월의 IC를 동일가중 평균하고 월별 종목 수·평가월 수·제외 사유를 함께 보고한다.

### MLP 추가 실험

`src/models/mlp.py`에는 활성화 함수·Optimizer 비교와 학습 안정성·강건성 검토 제안이 정리되어 있다. 추가 후보와 선택 기준을 확정한 뒤 별도 실험으로 관리하며, 위 기본 후보에는 자동 포함하지 않는다. RMSE·MAE는 보조 지표 제안이다.

```text
│   └── evaluation/          # 확장창·Rank IC
├── tests/                   # 특징·모형·기간·스키마·IC 검증 골격
├── data/
│   ├── raw/                 # 원본·외부 원문·공통 CSV
│   ├── interim/             # 정리 패널·공개시점 결합자료
│   └── processed/           # 특징·목표·공통 표본
├── models/                  # 학습된 모형·입력 변환기
└── outputs/
    ├── validation/          # 내부 검증 예측·월별 IC
    ├── final_test/          # 최종평가 예측·월별 IC·요약표
    └── run_id/              # 실행·검사·수정 이력
```

`src/models/`는 Python 모형 코드, 루트 `models/`는 학습 후 저장할 모형 객체와 입력 변환기를 위한 경로다.

## 7. 실험 설정

`config/experiment.yaml`에서 경로·열 대응·단위·시점 규칙·특징 정의·기간 분할·검증구간·모형 후보·난수값·평가 기준·표본 ID를 관리한다. 미확정 열 대응과 표본 ID는 `null`이다.

| 설정 | 내용 |
| --- | --- |
| `PATHS`, `COLUMN_MAPPING`, `UNITS`, `KEY_FORMATS` | 파일 경로·원본 열 대응·단위·식별자 형식 |
| `PIT`, `TIMEZONE`, `TARGET_MONTH_OFFSET` | 공개시점과 목표월 연결 |
| `H1`, `H3` | 기준 특징 계산 조건 |
| `H2`, `H4` | 확장 사용 여부와 정책사전·기업규모·검색·집계 명세 |
| `PERIODS`, `FOLDS` | 목표월 기간 구분과 연별 검증창 |
| `OLS`, `RIDGE`, `MLP` | 모형 설정과 후보·동률 규칙 |
| `EVALUATION`, `SAMPLE_ID` | 평가 규칙과 공통 표본 식별값 |
| `REPRODUCIBILITY_PREDICTION_ATOL` | 동일 조건 예측값 재현성 허용오차 `1e-10` |
| `FINAL_TEST_ENABLED`, `TEST_ACCESS_REQUIRES_FROZEN_CONFIG` | 최종평가 접근 설정 |

H2·H4의 기본 활성화 값은 `false`다. 활성 확장은 필수 명세를 설정한 뒤 처리하도록 설계한다. 비활성 확장의 결측으로 기준모형 표본을 줄이지 않는다.

공통 스키마는 `src/contracts.py`에서 관리한다. 기준 특징·표본 스키마에 활성 확장의 주효과·상호작용·가용성·제외 사유를 연결한다.

## 8. 개발 환경과 실행 방법

Python 3.11을 기준으로 하며 의존성은 `requirements.txt`에서 관리한다. 패키지 버전은 설치·호환성 확인 후 고정한다.

### 환경 생성

프로젝트 루트의 PowerShell에서 사용하는 명령이다.

```powershell
py -3.11 -m venv .venv
$runPython = '.\.venv\Scripts\python.exe'
$cfg = 'config/experiment.yaml'
& $runPython -m pip install -r requirements.txt
```

### 단계별 실행

다음은 파이프라인 구현 후 사용할 명령 형식이다. 현재 CLI 인자 처리와 단계 실행 함수는 미구현 상태이므로 명령 실행은 아직 지원하지 않는다.

```powershell
& $runPython -m src.pipeline --config $cfg --stage ingest
& $runPython -m src.pipeline --config $cfg --stage collect
& $runPython -m src.pipeline --config $cfg --stage features
& $runPython -m src.pipeline --config $cfg --stage validate
& $runPython -m src.pipeline --config $cfg --stage final-test
```

다섯 명령은 모두 `src/pipeline.py`를 진입점으로 사용하며 `--stage` 값으로 단계를 선택하는 구조다. 각 단계는 앞 단계 검사를 통과한 산출물을 입력으로 받는다.

| 단계 | 대응 함수 | 처리 내용 | 예상 산출물 |
| --- | --- | --- | --- |
| `ingest` | `plan_ingest()` | 기본자료 적재·정제 | `data/interim/panel.parquet` |
| `collect` | `plan_collect()` | 외부 수집·정제·공개시점 결합 | 원문·문서 목록·공통 CSV, `data/interim/asof.parquet` |
| `features` | `plan_features()` | 특징·차월 목표값·기간 분할 | `data/processed/features.parquet`, `data/processed/samples.parquet` |
| `validate` | `plan_validate()` | Train 내부 검증·설정 선택 | `outputs/validation/predictions.csv`, `outputs/validation/monthly_ic.csv` |
| `final-test` | `final_test()` | Train 전체 재학습·최종평가 | `models/`의 모형·변환기, `outputs/final_test/`의 예측·월별 IC·요약표 |

`final-test`는 최종평가 전용이다. Train 내부에서 모든 규칙을 확정하고 2001~2021년 전체 학습행으로 모형과 추가 학습형 변환기를 다시 적합한 뒤, Test를 최초로 열람·적재하여 한 번 평가한다. 현재 진입점은 접근 차단 상태다.

수집기와 분석기는 분리한다. 수집기는 원문·출처·공개시점·수집 상태를 보존하고, 분석기는 저장된 원문·추출문·정리자료를 사용한다. 재실행 시 기존 원문을 재사용하고 실패·재수집 범위만 구분하여 중복 수집을 방지한다.

## 9. 산출물과 오류 검사

| 산출물 | 주요 내용 |
| --- | --- |
| `features.parquet` | 종목·기준월·목표월, H1·H3·Mom, 확장 특징·가용성·제외 사유 |
| `samples.parquet` | 목표값·기간 구분·공통 표본 ID·제외 사유 |
| `predictions.csv` | model, candidate, fold, stock_id, target_month, yhat, y |
| `monthly_ic.csv` | model, candidate, fold, target_month, n, ic, reason |
| `outputs/run_id/` | 환경·버전·난수·파일 및 설정 식별값·명령·검사·수정 이력 |

필수 열 누락, 키 중복, 단위 불명, 미래정보 혼입은 후속 단계를 중단한다. 개별 자료 부재는 공통 유효 표본 규칙에 따라 처리하고, 제외 종목·기간·사유를 기록한다. 오류 수정 후에는 이전 정상 산출물부터 재실행한다.

## 10. 구현 상태

- H1·H2·H3·H4, OLS·Ridge·MLP, 전처리·평가·파이프라인은 함수 골격과 처리·검증 명세를 포함한다.
- YAML 설정 로딩을 제외한 데이터 처리·학습·예측·평가 함수는 미구현이다.
- `tests/`는 건너뛰기 처리된 검증 골격이며 기능 테스트는 아직 구현되지 않았다.
- CLI 실행, Python 3.11 환경의 설치·호환성, 기능·재현성 검증은 완료되지 않았다.
- 데이터·모형·평가 결과 파일은 아직 생성되지 않았다.
